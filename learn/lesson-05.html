Web Basics · Lesson 5 of 11 · Change control

Never lose work.
Never fear a mistake.

Change control means keeping track of every change to a project, who made it and why — so you can always see what happened and go back.

Two ways to keep track

The old way

Copying files and hoping

Which one is right? What changed? 🤷

The new way

One project, a clear history

Commit 2 of 5: “Add services section” — Tue · Tomas. You can open this version any time and see exactly what changed.

Each dot = a commit. Tap one to travel back in time.

The words that matter

Version — one saved state of your project at a moment in time. Like a save point in a video game.

Git — free software that tracks versions of your project for you. It's what nearly every professional developer uses.

Repository (or repo) — a project folder that Git is watching, including its whole history.

Commit — a save point you create on purpose, with a short message saying what changed, like “Add services section”.

GitHub — a website that stores your Git repos online. It's your backup, your history, and the place Netlify picks your code up from.

Push — sending your new commits from your computer up to GitHub.

Good commit messages are short and say what you did: “Change hero photo to Manly beach” beats “stuff”. Future-you (and your clients) will thank you.
