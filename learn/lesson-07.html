The shop window.
1 · Local. You (and Grok Bot) make the change on your own computer. Nobody else can see it yet.
2 · GitHub. You push your commits. GitHub stores the code and its history, then tells Netlify “new code!”
3 · Netlify build. Netlify automatically builds the site and publishes it to its servers. Which one it updates depends on where the code came from.
4 · Preview. Code from a branch or pull request goes to a private preview link — the changing room. Check it, and send it to the client for a thumbs-up.
5 · Live. Merge into main and the real site updates within a minute or two — the shop window.

The words that matter

Local — on your own computer. A local version is just for you; nobody else can see it.

Build — the step where a host takes your code and gets it ready to publish (for example, shrinking images and bundling files).

Preview — a temporary, private copy of the site with its own link, made for checking changes before they go live.

Live (or production) — the real, public website on the real domain.

The magic bit: once it's set up, you never “upload” anything. Merge on GitHub and Netlify does the rest. If a deploy ever goes wrong, Netlify keeps old deploys too, so you can switch back with one click.
