06 · Branches, pull requests & undo

Try things safely,
then make them real.

The live website shouldn't change until you're happy. Git lets you work on a side copy, check it, and only then add it to the real thing.

Main — the main line of your project’s history. Whatever is on main is what's on the live website.

Branch — a side copy of the project where you can try changes without touching main. Like a draft.

Pull request (or PR) — on GitHub, a request that says “please add my branch's changes into main”. It shows exactly what changed, line by line, so you can check before saying yes.

Merge — joining a branch's changes into main.

Roll back (or revert) — undoing a change by going back to an earlier version. Because every version is saved, nothing is ever truly lost.

The everyday loop

  1. Make a branch for the change, e.g. new-prices.
  2. Ask Grok Bot to make the change.
  3. Commit with a clear message and push to GitHub.
  4. Open a pull request.
  5. Netlify makes a preview link — check it on your phone and laptop.
  6. Happy? Merge. The live site updates by itself.
  7. Something broke? Roll back and breathe. Fix it calmly.
